# Удаление ветки после мержа

В проекте ветки вливаются в `main` через PR с merge-коммитом, поэтому влитость проверяется
простой проверкой предка. Ветку удаляют только когда она точно в `main`.

## 1. Убедиться, что ветка влита

```bash
git fetch origin --prune
gh pr view <ветка> --json state,mergedAt -q '.state'                   # ждём MERGED
git merge-base --is-ancestor <ветка> origin/main && echo merged        # ждём merged
```

Если хоть одна проверка не проходит (PR открыт или закрыт без мержа, в ветке есть коммиты не из `main`),
ничего не удалять, а сказать пользователю, что именно не влито (`git log origin/main..<ветка> --oneline`).

## 2. Освободить ветку

- Если это текущая ветка основной папки — сначала проверить `git status --porcelain`
  (незакоммиченное не терять, спросить пользователя), затем `git switch main && git pull --ff-only`.
- Если ветка открыта в worktree (`git worktree list`) — удалить worktree по навыку `worktree-cleanup`.
  Папку текущей сессии не удалять: сказать, что её уберёт очистка после архивации сессии.

## 3. Удалить

```bash
git branch -d <ветка>                          # -d, не -D: откажет, если ветка не влита
git ls-remote --exit-code --heads origin <ветка> && git push origin --delete <ветка>
```

Ветку на GitHub удалять, только если пользователь попросил удалить ветку или смержить с удалением
(это push, а пушим только по просьбе). GitHub может уже удалить её сам после мержа, отсюда проверка `ls-remote`.
Если мерж делаешь сам через `gh`, проще сразу: `gh pr merge <номер> --merge --delete-branch`.

## Пакетная очистка

Для «почисти старые ветки»: взять `git branch --merged origin/main`, исключить `main` и текущую ветку,
показать список и после подтверждения пройти шаги 2–3 для каждой.

В конце сказать, какие ветки удалены локально и на GitHub, а какие оставлены и почему.
