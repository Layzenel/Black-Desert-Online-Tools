# Несколько аккаунтов

На одном ПК могут играть с нескольких аккаунтов. Игра хранит их вперемешку:

| Что | Где | Чьё |
|---|---|---|
| Настройки аккаунта, порядок персонажей, раскладка интерфейса | `UserCache\<аккаунт>\gamevariable.xml` | аккаунта |
| Настройки персонажей | `UserCache\<аккаунт>\11\<персонаж>\gamevariable.xml` | аккаунта |
| Заметки персонажей | `UserCache\<аккаунт>\gameVariable_lobby.xml` | аккаунта |
| Портреты | `FaceTexture\<персонаж>.bmp` | **всех аккаунтов вместе** |
| Корень `UserCache\gamevariable.xml` | общий файл игры | не аккаунт |

`<аккаунт>` — номер папки в `UserCache` (только цифры). Аккаунт — папка, в чьём `gamevariable.xml` есть
`CharacterOrderList`. Персонажи аккаунта — ключи этого списка; по ним портреты из общей `FaceTexture` делятся
между аккаунтами.

## Где это в коде

- `platform/core/.../core/account/`: `GameAccounts` — список аккаунтов и выбранный (`state.selected`), общий
  для всего приложения (Koin `single`). `GameAccount.characterOrder` — его персонажи. `AccountChoice` помнит выбор.
- `shared/.../account/`: `AccountPicker` — окно выбора (при первом открытии его нельзя закрыть без выбора),
  `AccountSwitcher` — кнопка «Аккаунт» в верхней навигации, открывает то же окно.
- Фича узнаёт смену аккаунта, подписываясь на `GameAccounts.state` (`selectedId`), и перечитывает свои данные.

## Правила

1. **Всё, что тулза сама создаёт и что относится к персонажам или настройкам игры, лежит в папке аккаунта.**
   Шаблон пути — `<папка тулзы>\<аккаунт>\…`. Уже так сделано:
   - `FaceTexture_backup\<аккаунт>\<дата-время>` — резервные копии портретов;
   - `Favorite FaceTexture\<аккаунт>\<дата-время>` — избранное портретов;
   - `BDO Tools\slots\backups\<аккаунт>\…` — копии `gamevariable.xml` перед записью;
   - `BDO Tools\lobby_backup\<аккаунт>\…` — копии файла заметок.
   Новая папка или файл тулзы — сразу с папкой аккаунта, а не «потом доработаем».
2. **Общее для всех аккаунтов — только то, что не зависит от персонажей и игровых настроек аккаунта.**
   Сейчас это «Мои пресеты» редактора интерфейса (`BDO Tools\slots\presets`: раскладка с якорями переносится
   на любой аккаунт — так решил пользователь), подложка редактора и `BDO Tools\portraits` (файлы по ID персонажа,
   а ID уникальны между аккаунтами). Если сомневаешься, общее это или по аккаунту, — спроси пользователя до кода.
3. **Читать и писать — только выбранный аккаунт.** Списки (копии, наборы, пресеты по аккаунту) показывают только
   его папку. При смене аккаунта фича перечитывает данные и сбрасывает состояние, привязанное к старому аккаунту:
   выбор, кэши, открытые окна.
4. **Аккаунт передаётся явно.** Методы хранилища (`*Storage`, JS-мост) получают `account` параметром, а не
   угадывают его. `account = null` — аккаунтов не нашли (в `UserCache` нет списка персонажей): тогда папки без
   аккаунта, как в старых версиях.
5. **Старые данные без аккаунта переезжают, а не теряются.** Если меняешь место хранения, копии и наборы из
   прошлых версий при первом открытии переносятся в папку выбранного аккаунта (пример — `adoptLooseFolders`
   в `PortraitsStorage`: папки, чьё имя не номер аккаунта). Если в имени файла уже есть аккаунт — переносить
   по нему (копии слотов `gamevariable_<аккаунт>_…`).
6. **Обе платформы.** Пути одинаковые на Desktop (`java.nio.file`) и в браузере (JS-мост). В мосте метод получает
   не больше двух аргументов: аккаунт склеивается с папкой строкой `аккаунт/папка` (см. `FileSystemBridgeScript.kt`).
   Перемещать папки File System Access API не умеет — переносить копированием файлов и удалением.
7. **Тесты.** Хранилища в памяти для тестов (`MemoryStorage`) разделяют данные по аккаунтам; на новую папку
   по аккаунту — тест, что у другого аккаунта её содержимого не видно, и тест переноса старых данных.

## Проверка на втором аккаунте

Реального второго аккаунта у пользователя может не быть. Для ручной проверки:

1. Перед началом сохрани список файлов `Документы\Black Desert` (`find … -type f`), чтобы потом удалить ровно своё.
2. Создай `UserCache\<номер, которого нет>\gamevariable.xml` — копию файла настоящего аккаунта, где блок
   `CharacterOrderList` заменён своими ID (например `99000000000000001…`). Файл игры в Latin-1 — копируй байты,
   не перекодируя.
3. Положи портреты этих ID в `FaceTexture` — BMP 624×804, 32 бита (можно нарисовать через `System.Drawing`
   в PowerShell).
4. После проверки удали мок-папку, мок-портреты и всё, что программа создала для мок-аккаунта (сравни со списком
   из шага 1). Настоящие файлы не трогай. Пока мок-файлы на месте, игру лучше не запускать.

## Чек-лист

- [ ] новые файлы и папки тулзы — в `<…>\<аккаунт>\`, кроме того, что пользователь решил сделать общим;
- [ ] списки показывают только выбранный аккаунт, смена аккаунта перечитывает их;
- [ ] старые данные без аккаунта переносятся в папку аккаунта;
- [ ] Desktop и браузер пишут в одни и те же пути, есть тесты на разделение и перенос;
- [ ] README (раздел «Несколько аккаунтов») совпадает с тем, что общее, а что по аккаунту.
