# Файлы игры в «Документы\Black Desert»

Здесь собрано то, что уже выяснено про файлы игры. Сначала прочитай это, потом открывай сами файлы.
Узнал новое — допиши сюда (с датой и тем, как проверено), а не в память.

Где тулза хранит **свои** файлы — скилл `tool-folder`; несколько аккаунтов — скилл `multi-account`.

## Где что лежит

Путь из Git Bash: `"$USERPROFILE/Documents/Black Desert"`. Аккаунт пользователя — `3537922`.

```
Black Desert\
├─ UserCache\
│  ├─ gamevariable.xml                  корневой, ~2 КБ, настройки до входа — не трогаем
│  └─ <аккаунт>\                        имя папки — номер аккаунта (бывают служебные: -1, Layzen, 6000…)
│     ├─ gamevariable.xml               ФАЙЛ АККАУНТА, ~1,1 МБ: позиции интерфейса, настройки, порядок персонажей
│     ├─ gameVariable_lobby.xml         заметки окна «Персонажи аккаунта»: <CharacterMemo CharacterNo= Memo=/>
│     ├─ userCache                      бинарный: "PABR", int32 число записей по смещению 4, с 12 — записи
│     │                                 по 12 байт: int64 CharacterNo + int32 порядок
│     └─ 11\<CharacterNo>\gamevariable.xml   ФАЙЛ ПЕРСОНАЖА, ~100 КБ; регистр имени бывает gameVariable.xml
├─ FaceTexture\                         портреты
├─ Customization\<имя>                  пресет внешности, файл без расширения (см. «Пресеты внешности»)
├─ GameOption.txt                       настройки клиента текстом `ключ = значение` (см. ниже)
└─ BDO Tools\<модуль>\<аккаунт>\        файлы тулзы: uiEditor\…\backups, presets, background
```

- Копии файла аккаунта, которые делает редактор интерфейса перед записью:
  `BDO Tools\uiEditor\<аккаунт>\backups\gamevariable_<аккаунт>_<дата>_<время>.xml` (файлы персонажей —
  с `<CharacterNo>` в имени). Это готовая история для сравнения «до и после».
- Имён персонажей в папке нет нигде.

## Как читать

- Файл аккаунта большой — не читай его целиком. Ищи: `grep -a -n` (обязательно `-a`: из-за смешанной кодировки
  grep считает файл бинарным).
- Список папок: `ls -la --time-style=long-iso` (шаблон `*/` у `ls` в Git Bash ломается на папке `-1`).
- Запущена ли игра: `tasklist | grep -i BlackDesert` (`BlackDesert64.exe`; процесс под античитом, путь не виден).

## Кодировка и переводы строк

- Файлы **смешанные**: `MemoList`, `SkillCoolTimeMemo` (и, вероятно, `JewelPresetNameData`, `PetGroupName`) —
  Windows-1251, а `CommonMemo` — UTF-8. Чтение как UTF-8 и запись обратно портит кириллицу (EF BF BD).
  Любая запись — байт в байт (отображение Latin-1), никогда не через декодирование UTF-8.
- Переводы строк CRLF, отступ — табуляция. При правке руками: `sed -b`.
- Меняй только значения нужных атрибутов, остальной текст оставляй прежним (`GameVariableWriting.kt`).

## Когда игра пишет файлы

- Игра читает файлы при запуске, держит всё в памяти и **перезаписывает файлы из памяти**: при смене персонажа,
  телепорте, некоторых других действиях и выходе. Правка при запущенной игре будет затёрта.
  Писать можно только при закрытой игре (Desktop проверяет процесс, сайт просит подтвердить).
- При смене персонажа игра пишет файл аккаунта, `gameVariable_lobby.xml`, `11\gamevariable.xml` и через ≈5 с — файл
  персонажа, **с которого ушли**; файл персонажа, на которого зашли, не трогает (проверено 2026-11-26: Мудрец → Агент,
  записан только файл Мудреца). Поэтому новейший файл персонажа — предыдущий персонаж, а не текущий: какой персонаж
  в игре, по файлам в «Документах» не узнать — это видно в логе клиента (ниже).

## Лог клиента (`<папка установки игры>\Log`)

Найдено 2026-11-26 (клиент 4Game, `D:\Games\Black Desert Online\Log`). Пути установки в реестре нет, но программа
уже читает путь процесса игры (`foregroundGamePid` в `GameForeground.kt`: `QueryFullProcessImageName` с
`PROCESS_QUERY_LIMITED_INFORMATION`) — это `<папка установки>\bin64\BlackDesert64.exe`. Без прав администратора у
программы путь пустой (игра запущена от администратора), поэтому `ProcessHandle` его и не видел.
- `Client_<дата>_<время>.json` — по файлу на запуск игры, **UTF-16 LE**, первая строка `START_LOG(Version = …)`, дальше
  по JSON-объекту на строку: `{"Date":"2026-11-26 02:49:45","Thread":…,"LogType":…,"ErrNo":…,"ErrStr":…,"Log":"…"}`.
  Игра дописывает его сразу, пока работает; читать можно, пока он открыт игрой.
- Смена персонажа — две строки:
  `[Character Swap] Prepare Swap Info (<CharacterNo>,<имя>,a,b -> <CharacterNo>) (Mode:0)` и через ≈8 с
  `[Character Swap] Complete Swap Info (<CharacterNo>,<имя>,a,b -> <CharacterNo>,<имя>,a,b)` — после `->` персонаж,
  на которого зашли. Здесь же имена персонажей. Числа `a,b` не разобраны.
- Вход из лобби (`Active Processor (eProcessor_Lobby)` → `eProcessor_Loading` → `eProcessor_Play`) номера персонажа
  **не пишет**: до первой смены персонажа после входа лог не говорит, кто в игре. Файлы тоже (проверено 2026-11-26:
  перезапуск игры и вход на Мудреца — при входе записались только `GameOption.txt`, `ColorPalette.uc`, `11\worker.cache`
  и `UserCache\6000…\subLuaCacheData.txt`, номера персонажа нет ни в одном; при выходе из игры записался файл
  персонажа, на котором играли, и `userCache`). Выход в лобби или отключение —
  `eErrNoPcLogout` и снова `eProcessor_Lobby`.
- Рядом `StartupLog_*.log` (≈18 КБ на запуск).

## Кэш клиента (`<папка установки игры>\Cache\11`)

Найдено 2026-11-26, три входа подряд:
- `MyJournal\<CharacterNo>_<ггггмм>.bcf` (начало `PABR`, 33 байта и больше) игра пишет через ≈10 с после входа
  персонажа в мир (`Active Processor (eProcessor_Play)` в логе) — **и при первом входе из лобби, и при смене**:
  Мудрец вошёл 02:59:15 → файл 02:59:26; смена на Агента 03:03:36 → файл 03:03:36; новый запуск, вход на Exegi 03:12:25 →
  файл 03:12:35; вчерашняя смена на Клуйка 20:51:33 → файл 20:51:33. Новейший файл в `MyJournal` — текущий персонаж.
  Пишет ли игра его ещё и по ходу игры (записи журнала), не проверено; если да — это всё равно текущий персонаж.
- Формат `MyJournal` (разобран 2026-11-26 по двум файлам, смысл полей — догадки): `PABR`, int32 число записей по смещению
  4 и ещё раз по `0x11`, с `0x15` — записи по 29 байт: int64 время (unix, секунды), байт вида, 5 × uint32. В конце —
  ещё ≈17–70 байт, не разобраны. Виды: 2 (чаще всего) и 1 — похоже на заточку (первое число — ключ предмета в младших
  24 битах и уровень в старшем байте, третье — уровень цели; 2 — неудача, 1 — успех?), 0 — одно число (3826 → 3827),
  5 — одно число (68, 69), 4 — неизвестно. Игра дописывает запись и по ходу игры (Exegi, 11-26 03:29).
- `User*.bcf`, `Character*.bcf`, `Guild*.bcf`, `Maid_*` переписываются разом при выходе из игры — текущего персонажа не
  называют. Это кэш всех, кого клиент видел (2026-11-26: 1556 персонажей), — свои персонажи и **чужие игроки**: чужие
  имена, фамилии, описания гильдий, клички лошадей не собирать и никуда не отправлять. Все файлы — `PABR`, int32 число
  записей, дальше записи с int64 номером в начале. Разобрано 2026-11-26:
  - `Character_PcBasic.bcf` — **имена персонажей**: int64 `CharacterNo`, int32 (не разобран), имя UTF-16 LE до ≈30
    знаков с нулями. Есть у всех 32 персонажей аккаунта (`CharacterOrderList`) — единственное место с их именами.
  - `Character.bcf` — записи по 16 байт: `CharacterNo` + int64 время (unix, с), похоже, когда запись обновлена.
  - **Класса персонажа в кэше явно нет** (проверено 2026-11-26 на 32 персонажах аккаунта): int32 перед именем в
    `Character_PcBasic.bcf` с классом не совпадает (у двух Дос 1 и 2, у Агента и Мудреца — 6), в `Character.bcf`
    только время, `Character_Custom.bcf` (884 байта на персонажа) начинается с ползунков внешности. Косвенно класс
    видно по оружию в `Character_Equip.bcf` — нужен справочник предметов. Проще — по умениям файла персонажа (ниже).
  - `Character_Equip.bcf` — снаряжение, ≈3,4 КБ на персонажа: uint32 вида `0x090E3395` — ключ предмета в младших 24 битах,
    уровень заточки в старшем байте (те же числа, что в записях заточки `MyJournal`).
  - `WarehouseHistory_<аккаунт>.bcf` — история склада: int64 время, ключ предмета, количество, номер города (догадка).
  - Состояния интерфейса в кэше **нет**: `UserUi.bcf`, `UserUiInfo.bcf`, `UserGameOption.bcf`, `User_GameOption.bcf`,
    `Base.bcf`, `Quest.bcf` — 20–28 байт, только заголовок без данных (проверено 2026-11-26); `UIData`, `IsShow`,
    `SkillCoolTime` нет ни в одном файле кэша. Видимость элементов — только в `gamevariable.xml` (с его задержкой) и на экране.
  - `UserBasic.bcf` — фамилии и подписи семей, `Character_VehicleBasic.bcf` — клички лошадей, `Maid_Basic` — имена
    служанок, `Character_GuildBasic.bcf` — названия и описания гильдий (всё — в основном чужое).
- `GuildJournal\<гильдия>_<ггггмм>.bcf`, `WarehouseHistory_<аккаунт>.bcf` — тоже по ходу игры.
- В `AppData\Local` (4Game, Pearl Abyss, Innova) про персонажа и путь установки игры ничего нет.
- Изменение, сделанное в игре, попадает в файл только после такого события. Свежая настройка или новый порядок
  персонажей в файле не появятся, пока игрок не сменит персонажа или не выйдет.

## Файл аккаунта

- Экран: первое `<Resolution Width Height/>` и первое, верхнего уровня `<UiScale Value/>` («Размер интерфейса»,
  100% → `1`). Размер экрана в UI-px = разрешение / UiScale (2560×1440 при 0.8 → 3200×1800).
- `<UIData Index= IsShow= PendingType= PosX= PosY= RelativePosX= RelativePosY=/>` — элемент интерфейса.
  `RelativePosX/Y` — **центр** элемента в долях экрана. При смене масштаба доли сохраняются, `PosX/PosY`
  игра пересчитывает сама. У части записей есть `SizeX/SizeY`, `IsPinHold`.
- `UISettingPreset0..2` — те же записи для пресетов интерфейса 1–3 игры (`GamePreset` в коде).
- `<UIValue Version="4">` — список `<Number Index= Value= StorageType="1"/>` и `<Bool Index= Value= StorageType="1"/>`:
  живые значения настроек интерфейса. `<GameOptionCustomize>` (`UseNewQuickSlot` и т. п.) — только сохранённая
  копия пресета настроек, не живое значение.
- `<CharacterOrderList …/>` — порядок персонажей.

### История использования навыков (`Index="158"`)

Проверено 2026-11-13: включение в игре и смена персонажа, затем три скриншота 2560×1440 при `UiScale` 0.8.
- В файле аккаунта `<UIData Index="158" IsShow= PendingType= PosX= PosY= RelativePosX= RelativePosY=/>`, в файле
  персонажа — `IsShow`. По словам пользователя, видимость привязана к пресетам интерфейса игры.
- `IsShow` в файле персонажа отстаёт от игры (2026-11-25: включено в игре и в файле аккаунта, а в файле
  персонажа `false` с утра — он не переписывался). Поэтому трекер считает историю видимой, если хоть раз прочитал её
  с экрана (`ScreenSkillHistorySource.historyShown`), а файл — только запасной признак.
- Пример: `LeftBottom`, `PosX="2" PosY="134"`, `RelativePos` 0.0319 / 0.7474 → центр ≈ (82, 1076) px; на скриншоте
  строки занимают x ≈ 0–180, y ≈ 1040–1105 px.
- До 3 строк, прижаты к низу: новая всегда в нижней строке, старые сдвигаются вверх. Иконка умения (≈26 px) только у
  нижней строки, текст начинается на ≈32 px правее левого края. Шаг строк ≈22 px, шрифт ≈14 px.
- Строки гаснут **все разом** через ≈2 с после последнего умения; следующее умение начинает историю заново с одной
  строки.
- Новое умение: строки сразу сдвигаются вверх, а нижняя строка 120–370 мс пустая, потом появляются текст и иконка
  (иногда иконка сразу). Пустая нижняя строка при видимых верхних — надёжный признак нового применения, в том числе
  повтора того же умения. Повтор одного умения — отдельные одинаковые строки («Разрубание IV» ×3).
- Иконка нижней строки: 30×30 px, левый верхний угол ≈ (1, 1080) px при 2560×1440 и `UiScale` 0.8. Иконка
  справочника (44×44), уменьшенная до 30 px, с круглой маской: известные умения — средняя разница 12–23 при
  втором кандидате ≥ 42; умения, которых нет в справочнике, — 36–57 без отрыва. «Зарево IV» и «Мощь: Зарево» —
  одна иконка (17,6 и 20,3), их различает только текст или стойка.
- Умения без перезарядки («Пронзающий удар», «Разрубание», «Комбо: Взрывной толчок») — в отдельном справочнике
  `https://layzenel.github.io/bdo-tools-data/skills-no-cooldown.json` (тот же формат, пассивных нет). Нет нигде:
  «Пробуждение: Двуручный меч» (смена оружия) и навыки, которых нет в деревьях bdolytics, — улучшения навыков
  («Wolf's Explosive Fangs») и, похоже, отдельные версии навыков наследия Страйкера с иконками 5367–5371 по bdoclasshub.
- Захват области 240×120 через GDI `CopyFromScreen` (замер 2026-11-13, 479 кадров): 4,8 мс в среднем, 7,5 мс 95%,
  максимум 14,6. Длинные названия не помещаются в 240 px, для текста нужно ≈340.
- Подложки нет: текст с тёмной тенью прямо поверх мира, поэтому фон под ним постоянно меняется. Цвет текста —
  белый, а у «Мощь: …» красно-оранжевый, около `#F09664` (скриншот 2026-11-14); у других категорий может быть свой.
- Названия на языке клиента, с рангом римскими цифрами («Удар щитом III»).

### Слоты перезарядок на экране (`Index` 128–137, 148–157)

Запись экрана 2026-11-18 (2560×1440, «Размер интерфейса» 80 %, Страйкер в бою):
- Центр слота — `RelativePosX/Y` × разрешение, совпадает до пикселя; слот — 50 единиц интерфейса (40 px при 80 %).
  Умение в слоте — `SkillCoolTimeSlot SlotNo` файла персонажа (слоты 0–9 → `Index` 128–137, 10–19 → 148–157).
- Готовый слот — цветная иконка в рамке. На перезарядке иконки нет: тёмный квадрат с белыми «5 с.» / «4 м.»,
  иконка проявляется обратно постепенно. Средняя цветность (max − min канала) середины слота за один кадр
  падает с ≈50–70 до ≈13, затем за секунды поднимается. Серая иконка (пустой/неактивный слот) — цветность ≈7.
- Какой персонаж в игре, файлы в «Документах» не говорят: его даёт журнал в папке установки (раздел «Кэш клиента»).
- Хотбар: `QuickSlotSkillData Key="0..19" SkillNo=` в файле персонажа (`QuickSlotItemData` — предметы), места —

### Чаты (`Index="32"`)

- `WindowIndex` 0 — главное окно; остальные с `IsCombinedToMainPanel="true"` — его вкладки, с `"false"` — отдельные окна.
- `RelativePosX/Y` — центр окна, `SizeX/SizeY` — размер в UI-px. `IsShow` — глазик; скрытый главный чат прячет все окна.
- Сверху окна — плашка вкладок ≈26 UI-px, она входит в `SizeY`: рамка режима правки совпадает с `SizeY`, а сообщения
  начинаются под плашкой (скриншоты 2560×1440 при 0.8, 2026-11-25; `CHAT_TAB_BAR_HEIGHT` в редакторе).
- Блокировки окна в этих файлах нет (`IsOpen` есть только в `UISettingPreset*`).
- В файле персонажа — 5 записей `<UIData Index="32" IsShow=…/>` без `WindowIndex`, в том же порядке, что записи
  чатов в файле аккаунта.

## Файл персонажа

- В `11\` лежат и папки **удалённых персонажей**, и служебная `-1` (2026-11-12: 37 папок при 32 персонажах).
  Персонажи аккаунта — только те, что есть в `CharacterOrderList` файла аккаунта; остальные папки не показывать.
- `<ShortcutKey_Action_Key InputType= keyCode=/>` — клавиши действий персонажа (у каждого свои). `InputType` совпадает
  с `{KeyBind:<действие>}` в командах навыков bdolytics (`Dash`, `Attack1`, `CrouchOrSkill`…), `keyCode` — виртуальный
  код клавиши Windows (1 — ЛКМ, 2 — ПКМ, 16 — Shift, 32 — Space, 65–90 — буквы), 0 — клавиши нет.
  Рядом `ShortcutKey_Action_Pad` (геймпад) и `ShortcutKey_UI_*` (окна) — их не путать.
- `<UIData Index= IsShow=/>` — **видимость у каждого персонажа своя**; позиции — одни на аккаунт (в файле аккаунта).
  Меняешь видимость — пиши её и в файлы персонажей.
- `<SkillCoolTimeSlot SlotNo="0..19" SkillNo=/>` — навык в слоте перезарядки (0 — пусто).
- `<SkillCoolTimeMemo SkillNo= Memo=/>` — подпись, по `SkillNo`, а не по слоту (cp1251).
- `SkillNo` = id навыка на bdolytics: `https://bdolytics.com/ru/db/skill/<id>`, данные —
  `https://bdolytics.com/api/trpc/database.getSkill?input={"id":"<id>","language":"ru"}`. У каждого ранга свой id.
- Класса персонажа в файлах нет. Его определяют по `SkillNo` из слотов через справочник навыков (классы, ветка,
  названия RU/EN, иконка): `https://layzenel.github.io/bdo-tools-data/skills.json`, иконки —
  `https://layzenel.github.io/bdo-tools-data` + поле `icon` (репозиторий `Layzenel/bdo-tools-data`, обновляется
  каждый день, вшитой копии в приложении нет). В справочнике только навыки с перезарядкой: этого хватает для
  слотов перезарядки, но часть навыков хотбара (`QuickSlotSkillData`: без перезарядки, «Flow:», от предметов)
  в нём нет. Неизвестный `SkillNo` не блокирует работу, а класс `class-<номер>` — новый класс, ещё не внесённый
  в таблицу.
  Часть навыков общая для пары классов или для всех —
  класс = пересечение классов всех навыков. Проверено 2026-11-11 на 12 персонажах аккаунта: класс находится однозначно.
- Слоты перезарядки пусты — класс видно и по другим записям с `SkillNo` в файле персонажа (проверено 2026-11-12
  на 32 персонажах аккаунта через справочник: по слотам класс есть у 11, со всеми тремя источниками — у 28,
  противоречий нет): `<QuickSlotSkillData Key= SkillNo= …/>` — навыки на хотбаре; `<SkillCommandLock>` с дочерними
  `SkillNo` — навыки с заблокированной командой (`0` — пусто). Оставшиеся 4 — навыки без перезарядки, которых нет
  в справочнике, или пустые записи. `QuickMenuInfo SkillKey` у всех пуст. В приложении пока не используется.
- Ключи классов в справочнике — `CharacterClass.key`, а enum назван по русской локализации:
  Tamer — «Мистик» (`mystic`), Mystic — «Фурия» (`fury`).

## Пресеты внешности (`Customization\<имя>`)

Разобрано 2026-11-11 по одному файлу `striker` (924 байта) через `xxd`:
- Имя файла = имя пресета, расширения нет. Превью внутри нет, рядом картинок тоже нет.
- Байты 0–3 — int32 LE `20` (вероятно, версия или размер заголовка). Дальше 920 байт = 115 блоков по 8 байт,
  зашифрованных 8-байтовым блочным шифром в режиме ECB: блок `41ef586af7ca4f0e` повторяется 78 раз —
  это, скорее всего, зашифрованные нули. Значит, внутри разреженный массив параметров.
- Расшифровку не делали: ключ пришлось бы доставать из клиента игры. Для тулзы хватит работы с файлом целиком
  (копировать, переименовывать, импорт и экспорт), содержимое не трогать.

## Как найти, где хранится настройка игры

По одному файлу поле не угадать — нужны два снимка, «до» и «после»:

1. Сохрани текущие файл аккаунта и файл персонажа в scratchpad (`cp -p`). Проверь по времени изменения,
   что они свежее последнего переключения, иначе это не «до».
2. Попроси пользователя переключить настройку в игре и **сменить персонажа или выйти** — без этого файл не обновится.
3. Сравни: `diff <(tr -d '\r' < до) <(tr -d '\r' < после)`. Смотри `<Bool>`/`<Number>` в `<UIValue>` и
   `IsShow`/позиции `UIData`; то же — в файле персонажа.
4. Сначала проверь копии в `BDO Tools\uiEditor\<аккаунт>\backups`: возможно, нужная пара уже есть.
5. Результат запиши в таблицы выше.
