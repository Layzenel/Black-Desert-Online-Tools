# Файлы игры в «Документы\Black Desert»

Здесь собрано то, что уже выяснено про файлы игры. Сначала прочитай это, потом открывай сами файлы.
Узнал новое — допиши сюда (с датой и тем, как проверено), а не в память.

Где тулза хранит **свои** файлы — скилл `tool-folder`; несколько аккаунтов — скилл `multi-account`.

## Где что лежит

Путь из Git Bash: `"$USERPROFILE/Documents/Black Desert"`. Аккаунт пользователя — `3537922`.

```
Black Desert\
├─ UserCache\
│  ├─ gamevariable.xml                  корневой, ~2 КБ, настройки до входа — не трогаем
│  └─ <аккаунт>\                        имя папки — номер аккаунта (бывают служебные: -1, Layzen, 6000…)
│     ├─ gamevariable.xml               ФАЙЛ АККАУНТА, ~1,1 МБ: позиции интерфейса, настройки, порядок персонажей
│     ├─ gameVariable_lobby.xml         заметки окна «Персонажи аккаунта»: <CharacterMemo CharacterNo= Memo=/>
│     ├─ userCache                      бинарный: "PABR", int32 число записей по смещению 4, с 12 — записи
│     │                                 по 12 байт: int64 CharacterNo + int32 порядок
│     └─ 11\<CharacterNo>\gamevariable.xml   ФАЙЛ ПЕРСОНАЖА, ~100 КБ; регистр имени бывает gameVariable.xml
├─ FaceTexture\                         портреты
├─ Customization\<имя>                  пресет внешности, файл без расширения (см. «Пресеты внешности»)
├─ GameOption.txt                       настройки клиента текстом `ключ = значение` (см. ниже)
└─ BDO Tools\<модуль>\<аккаунт>\        файлы тулзы: uiEditor\…\backups, presets, background
```

- Копии файла аккаунта, которые делает редактор интерфейса перед записью:
  `BDO Tools\uiEditor\<аккаунт>\backups\gamevariable_<аккаунт>_<дата>_<время>.xml` (файлы персонажей —
  с `<CharacterNo>` в имени). Это готовая история для сравнения «до и после».
- Имён персонажей в папке нет нигде.

## Как читать

- Файл аккаунта большой — не читай его целиком. Ищи: `grep -a -n` (обязательно `-a`: из-за смешанной кодировки
  grep считает файл бинарным).
- Список папок: `ls -la --time-style=long-iso` (шаблон `*/` у `ls` в Git Bash ломается на папке `-1`).
- Запущена ли игра: `tasklist | grep -i BlackDesert` (`BlackDesert64.exe`; процесс под античитом, путь не виден).

## Кодировка и переводы строк

- Файлы **смешанные**: `MemoList`, `SkillCoolTimeMemo` (и, вероятно, `JewelPresetNameData`, `PetGroupName`) —
  Windows-1251, а `CommonMemo` — UTF-8. Чтение как UTF-8 и запись обратно портит кириллицу (EF BF BD).
  Любая запись — байт в байт (отображение Latin-1), никогда не через декодирование UTF-8.
- Переводы строк CRLF, отступ — табуляция. При правке руками: `sed -b`.
- Меняй только значения нужных атрибутов, остальной текст оставляй прежним (`GameVariableWriting.kt`).

## Когда игра пишет файлы

- Игра читает файлы при запуске, держит всё в памяти и **перезаписывает файлы из памяти**: при смене персонажа,
  телепорте, некоторых других действиях и выходе. Правка при запущенной игре будет затёрта.
  Писать можно только при закрытой игре (Desktop проверяет процесс, сайт просит подтвердить).
- Изменение, сделанное в игре, попадает в файл только после такого события. Свежая настройка или новый порядок
  персонажей в файле не появятся, пока игрок не сменит персонажа или не выйдет.

## Файл аккаунта

- Экран: первое `<Resolution Width Height/>` и первое, верхнего уровня `<UiScale Value/>` («Размер интерфейса»,
  100% → `1`). Размер экрана в UI-px = разрешение / UiScale (2560×1440 при 0.8 → 3200×1800).
- `<UIData Index= IsShow= PendingType= PosX= PosY= RelativePosX= RelativePosY=/>` — элемент интерфейса.
  `RelativePosX/Y` — **центр** элемента в долях экрана. При смене масштаба доли сохраняются, `PosX/PosY`
  игра пересчитывает сама. У части записей есть `SizeX/SizeY`, `IsPinHold`.
- `UISettingPreset0..2` — те же записи для пресетов интерфейса 1–3 игры (`GamePreset` в коде).
- `<UIValue Version="4">` — список `<Number Index= Value= StorageType="1"/>` и `<Bool Index= Value= StorageType="1"/>`:
  живые значения настроек интерфейса. `<GameOptionCustomize>` (`UseNewQuickSlot` и т. п.) — только сохранённая
  копия пресета настроек, не живое значение.
- `<CharacterOrderList …/>` — порядок персонажей.

### Известные `UIValue`

| Запись | Настройка |
|---|---|
| `Bool Index="1"` | «Настройка быстрых слотов»: `true` — 20 отдельных слотов, `false` — одна панель (Index 12). При выключении игра ставит `IsShow`: 12 → true, хотбар → false, 160 → false — в файле аккаунта и в файле текущего персонажа; `UISettingPreset*` не меняет |
| `Bool Index="72"` | «Разделение HP», **обратное** значение: `false` — здоровье, PVP и гнев отдельно (13, 84, 85), `true` — одна панель 138. При переключении игра меняет `IsShow` у 13, 84, 85, 138, 2 в файле аккаунта и в файле текущего персонажа и двигает 114. Найдено 2026-11-11 сравнением двух сохранений подряд |

### Чаты (`Index="32"`)

- `WindowIndex` 0 — главное окно; остальные с `IsCombinedToMainPanel="true"` — его вкладки, с `"false"` — отдельные окна.
- `RelativePosX/Y` — центр окна, `SizeX/SizeY` — размер в UI-px. `IsShow` — глазик; скрытый главный чат прячет все окна.
- Блокировки окна в этих файлах нет (`IsOpen` есть только в `UISettingPreset*`).
- В файле персонажа — 5 записей `<UIData Index="32" IsShow=…/>` без `WindowIndex`, в том же порядке, что записи
  чатов в файле аккаунта.

## Файл персонажа

- В `11\` лежат и папки **удалённых персонажей**, и служебная `-1` (2026-11-12: 37 папок при 32 персонажах).
  Персонажи аккаунта — только те, что есть в `CharacterOrderList` файла аккаунта; остальные папки не показывать.
- `<ShortcutKey_Action_Key InputType= keyCode=/>` — клавиши действий персонажа (у каждого свои). `InputType` совпадает
  с `{KeyBind:<действие>}` в командах навыков bdolytics (`Dash`, `Attack1`, `CrouchOrSkill`…), `keyCode` — виртуальный
  код клавиши Windows (1 — ЛКМ, 2 — ПКМ, 16 — Shift, 32 — Space, 65–90 — буквы), 0 — клавиши нет.
  Рядом `ShortcutKey_Action_Pad` (геймпад) и `ShortcutKey_UI_*` (окна) — их не путать.
- `<UIData Index= IsShow=/>` — **видимость у каждого персонажа своя**; позиции — одни на аккаунт (в файле аккаунта).
  Меняешь видимость — пиши её и в файлы персонажей.
- `<SkillCoolTimeSlot SlotNo="0..19" SkillNo=/>` — навык в слоте перезарядки (0 — пусто).
- `<SkillCoolTimeMemo SkillNo= Memo=/>` — подпись, по `SkillNo`, а не по слоту (cp1251).
- `SkillNo` = id навыка на bdolytics: `https://bdolytics.com/ru/db/skill/<id>`, данные —
  `https://bdolytics.com/api/trpc/database.getSkill?input={"id":"<id>","language":"ru"}`. У каждого ранга свой id.
- Класса персонажа в файлах нет. Его определяют по `SkillNo` из слотов через справочник навыков (классы, ветка,
  названия RU/EN, иконка): `https://layzenel.github.io/bdo-tools-data/skills.json`, иконки —
  `https://layzenel.github.io/bdo-tools-data` + поле `icon` (репозиторий `Layzenel/bdo-tools-data`, обновляется
  каждый день, вшитой копии в приложении нет). В справочнике только навыки с перезарядкой: этого хватает для
  слотов перезарядки, но часть навыков хотбара (`QuickSlotSkillData`: без перезарядки, «Flow:», от предметов)
  в нём нет. Неизвестный `SkillNo` не блокирует работу, а класс `class-<номер>` — новый класс, ещё не внесённый
  в таблицу.
  Часть навыков общая для пары классов или для всех —
  класс = пересечение классов всех навыков. Проверено 2026-11-11 на 12 персонажах аккаунта: класс находится однозначно.
- Ключи классов в справочнике — `CharacterClass.key`, а enum назван по русской локализации:
  Tamer — «Мистик» (`mystic`), Mystic — «Фурия» (`fury`).

## Пресеты внешности (`Customization\<имя>`)

Разобрано 2026-11-11 по одному файлу `striker` (924 байта) через `xxd`:
- Имя файла = имя пресета, расширения нет. Превью внутри нет, рядом картинок тоже нет.
- Байты 0–3 — int32 LE `20` (вероятно, версия или размер заголовка). Дальше 920 байт = 115 блоков по 8 байт,
  зашифрованных 8-байтовым блочным шифром в режиме ECB: блок `41ef586af7ca4f0e` повторяется 78 раз —
  это, скорее всего, зашифрованные нули. Значит, внутри разреженный массив параметров.
- Расшифровку не делали: ключ пришлось бы доставать из клиента игры. Для тулзы хватит работы с файлом целиком
  (копировать, переименовывать, импорт и экспорт), содержимое не трогать.

## `GameOption.txt`

Найдено 2026-11-11: текст, 117 строк `ключ = значение` (`version = 4`, `width`, `height`, `windowed`,
`graphicOption`, `SSAO`, `fov`, `gamma`, звук и т. д.). Настройки клиента, общие для всех аккаунтов.
Подходит для профилей графики. Когда игра его перезаписывает, не проверяли — считай, как с остальными файлами:
писать только при закрытой игре.

## Как найти, где хранится настройка игры

По одному файлу поле не угадать — нужны два снимка, «до» и «после»:

1. Сохрани текущие файл аккаунта и файл персонажа в scratchpad (`cp -p`). Проверь по времени изменения,
   что они свежее последнего переключения, иначе это не «до».
2. Попроси пользователя переключить настройку в игре и **сменить персонажа или выйти** — без этого файл не обновится.
3. Сравни: `diff <(tr -d '\r' < до) <(tr -d '\r' < после)`. Смотри `<Bool>`/`<Number>` в `<UIValue>` и
   `IsShow`/позиции `UIData`; то же — в файле персонажа.
4. Сначала проверь копии в `BDO Tools\uiEditor\<аккаунт>\backups`: возможно, нужная пара уже есть.
5. Результат запиши в таблицы выше.
